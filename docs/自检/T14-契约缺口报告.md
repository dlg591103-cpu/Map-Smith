# T14 契约缺口报告：table 图层缺数据行

> 状态：**建议（未确认）**。本报告只陈述证据与建议改动点，不擅自修改 `io/`（归数据管家窗口，见 SPEC 6.1）。
> 待团队确认后，由数据管家窗口补上；制图师窗口的 `analyze.join` 已按「正确契约」实现，缺数据时明确报错而不静默。

## 1. 问题

`analyze` 的 `join` op（facts/05 工具 3）需要把「无几何统计表」关联到行政边界，产出带统计值的面图层（choropleth 的数据源）。

但当前 `io/` 对无坐标 CSV 的解析结果里，**统计表的实际数据行没有被保存**：

- `src/mapsmith/io/models.py` 的 `DataLayer` 唯一的「数据」载体是 `gdf`（`GeoDataFrame | None`），没有独立字段存无几何表格。
- `src/mapsmith/io/uploads.py:65-78` 解析无坐标 CSV 时返回 `kind="table"` 的 `DataLayer`，`gdf=None`，
  `meta` 里只有 `columns`（列名）与 `crs_status`，`df` 数据行在函数返回时被丢弃。

## 2. 证据

`io/uploads.py`（`_csv_to_layer` 无经纬度分支）：

```python
if lon_col is None or lat_col is None:
    # 统计表：无坐标，供分级设色使用；几何关联由 analyze(join) 负责（T14）。
    return DataLayer(
        kind="table",
        name=name,
        source=f"上传文件 {name}",
        summary=summary,
        crs=None,
        meta={"encoding": encoding, "columns": columns, "crs_status": "not_applicable"},
    )
```

`io/models.py`（`DataLayer`）：

```python
@dataclass
class DataLayer:
    kind: LayerKind            # admin / point / raster / table
    name: str
    source: str
    summary: str
    gdf: gpd.GeoDataFrame | None = None   # 唯一的数据载体
    crs: str | None = None
    meta: dict[str, Any] = field(default_factory=dict)
```

`test_uploads.py:63-72` 亦确认 `table` 图层 `gdf is None`。

## 3. 影响

- `analyze.join` 无法从第一参数（统计表 DataLayer）取到数据行，`join` 链路在当前 `io/` 实现下无法端到端跑通。
- 制图师窗口无法改 `io/`（归数据管家），因此按正确契约先行实现，测试用「带数据行的假统计表」验证了 `join` 逻辑本身。

## 4. 建议改动点（数据管家窗口，待确认）

最小改动二选一：

1. **（推荐）`io/models.py` 增加表格字段**：给 `DataLayer` 增加 `table: pd.DataFrame | None = None`，
   无坐标 CSV 解析时把数据行放进 `table`，`gdf` 仍为 `None`。
2. **改 `io/uploads.py` 保存数据行**：把 `df` 序列化或存进 `meta`（不推荐，`meta` 语义是轻量元数据，不宜放大表）。

同步改动点：

- `uploads.py` 无坐标 CSV 分支：把 `df` 存入新字段，`meta["columns"]` 保留列名。
- `models.py`：新增字段与类型注解（需 `import pandas as pd`，注意不要引入循环依赖）。
- `test_uploads.py`：补一条断言「table 图层携带数据行」。
- `tools/analyze.py` 的 `join_table`：改为优先从新字段取数据行（`gdf` 兜底），并在 docstring 更新契约前提。
