## 1. 交付物

```
run.ps1               Windows 一键启动（UTF-8 BOM；找解释器 → 建 venv → 按锁装依赖 → python -m mapsmith）
run.sh                跨平台一键启动（bash；逻辑同上，参数 --host / --port）
Dockerfile            python:3.12-slim；先拷 requirements.lock 装依赖，再拷 src/ 与 web/dist/
docker-compose.yml    docker compose up：端口 8501、产物卷 ./out、LLM 环境变量透传
.dockerignore         构建上下文裁剪（.git、.venv、docs、web/node_modules 等不入镜像）
```

设计要点：

- 入口统一复用 `python -m mapsmith`（T22 第二段入口，`__main__.py` 注明「T23 的一键启动脚本复用本入口」）。
- `src/requirements.lock` 为 `pip freeze` 格式且不含平台专属包，Windows 与 Linux 容器共用同一份。
- `run.ps1` 兼容 SPEC 第 5 节所述「WindowsApps 存根排在前面」的本机环境：存根被版本检查排除，找不到解释器时给出 `MAPSMITH_PYTHON` 显式指定指引，不猜默认值。
- zip 以 `git archive --format=zip -o mapsmith-v0.1.0.zip HEAD` 生成（内容与固定提交一一对应，天然排除 `.venv/`、`out/` 等本地产物）。

## 3. 自检过程与发现的问题

1. **`run.ps1` 编码问题**：首版以 UTF-8 无 BOM 保存，Windows PowerShell 5.1 按 ANSI(GBK) 解析，中文注释与字符串被读成乱码并破坏引号结构，解析报错。修复：重写为 UTF-8 with BOM，并用 `PSParser::Tokenize` 校验语法通过。
2. **stderr 触发误停**：依赖就绪检查 `& $venvPython -c "import mapsmith" 2>$null` 在 `$ErrorActionPreference = "Stop"` 下，import 失败的 stderr 输出被转为异常导致脚本终止。修复：检查包进 `try/catch` 并临时放宽错误偏好。
3. 以上两处修复后重测，全链路通过；修复提交经 `--amend` 并入交付提交 `19ab167`。
