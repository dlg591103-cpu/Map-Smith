## 3. 关键设计

- **纯函数与控件分离**：Streamlit 组件难测，计算全部收进 `ui.py`；`app.py` 只做 `st.*` 控件与 `try/except` 错误回显。理由见任务第 3 节「结构要求」。
- **build_spec 前置校验**：断点数量 == n、图种白名单、标题非空等校验在 pydantic 之前做，报错信息面向用户（中文）；pydantic 的 `ValidationError` 兜底转成 `DataError` 中文说明，不让裸 traceback 冒到界面。
- **上传 CRS 状态机**：`parse_upload` 返回 `crs_status`；缺 CRS 时用 `st.session_state` 暂存临时文件，`st.radio` 让用户选坐标系，确认后 `parse_upload(path, crs=...)` 重新解析，不静默默认 4326。
- **choropleth 数据来源**：优先用上传的带数值字段面图层；否则用 `aggregate_points_to_admin` 把站点值按空间归属（`sjoin` predicate=within）聚合成面均值，无站点面为 NaN（渲染层按缺失灰色处理）。
- **PDF 出口**：三个渲染器加 `pdf_path` 参数与 `out_path` 并列，均不传则均不落盘，`render(spec, gdf, **kwargs)` 透传，保持现有 207 用例语义不变。
- **错误回显**：`app.py` 外层 `except DataError` 用 `st.error(str(e))`，`except Exception` 兜底给 `类型名：消息`，不抛裸 traceback。

## 4. 已知项与未做

- **buffer / overlay 缺口**：界面禁用并写明原因；`build_spec` 对这两个图种抛 `DataError`（带中文说明），`render()` 仍会抛 `NotImplementedError`。这是 SPEC 契约缺口，待决策。
- **不接 LLM / loop.py / agents/prompts**：本段 spec 由表单直接构造，一句话输入（LLM 解析）留第二段。
- **choropleth 演示数据**：徐州 demo_data 只有 5 个有效站点、覆盖约 2%，站点聚合到 10 个区县面后多数面为 NaN（灰色）。这与数据侧 T10「IDW 样例缺失」是同一缺口，本段不改数据侧。
- **上传字段选择**：`指标字段` 下拉框是固定白名单（`PM2_5_24h` 等），上传文件若字段名不同会在渲染时报「没有字段」的中文错误（符合错误回显要求），未做按上传文件动态列出字段。

### 修订 1：点图出图范围修复

**问题**：point 渲染沿用 `spec.extent.bbox`（行政区全幅）作为取景范围，站点稀疏时全挤在正中一小团。徐州真实数据：extent 宽 2.3116°（116.3571 → 118.6687），10 站外接框宽仅 0.3094°（117.1660 → 117.4754），站点占图幅宽度仅 **13.38%**，气泡与标注重叠、比例尺 50 km 与实际显示范围对不上。

**修复**：新增 `render/extent.py::drawing_extent(spec, *, content_bounds, pad, min_ratio)`——取内容外接框向外扩 pad 比例、与 extent 求交（不越界）、零面积/极小内容回退 extent。point 渲染传入 `frame.total_bounds`（spec.crs 下）收窄取景；`draw_notes`/`apply_layout` 增加 `extra_note` 透传，取景范围 <30% extent 宽度时注记「站点仅覆盖图幅局部，范围约 X km」。

**修复前后对比**：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 取景宽度 | 2.3116°（extent 全幅） | 0.3713°（117.1351 → 117.5063） |
| 站点占图幅宽度比例 | 13.38% | **83.33%** |
| 出图 | `point_demo.png` 186084 B | `point_fixed.png` 204679 B |

**判据局限**：可读性判据用「站点外接框占图幅宽度比例 ≥ 50%」（`test_point_content_occupies_at_least_half_frame`）+ 像素级「标注 bbox 两两不重叠」（`test_point_labels_do_not_overlap`）。局限：比例是数据坐标空间的必要前提，不充分——气泡本身有面积、标注有文字像素宽度，站点极密时即便比例达标仍可能轻微重叠；比例未折算 `set_aspect` 修正后图内实际像素比例。故加了标注重叠的像素级判据作为补充。

**IDW 待评估项**：IDW 是规则网格 + `imshow`，其 `extent` 直接对应栅格范围，改取景会牵动栅格裁剪与凸包掩码，本任务未改（任务范围外）。IDW 是否同样存在「站点稀疏时取景过宽」的问题，待后续评估。

**测试**：`test_extent.py` 9 用例（drawing_extent 退化/裁剪 6 + point 集成 3）。全量回归 `234 passed`（225 + 9）。
