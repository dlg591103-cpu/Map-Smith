## 交付物

- **软件包**：GitHub Release 附 `mapsmith-<version>.zip`，包含源码、依赖锁、`demo_data/` 离线数据与一键启动脚本（Windows `run.ps1`、跨平台 `run.sh`）。
- **容器**：仓库提供 `Dockerfile` 与 `docker compose up`，评委不装 Python 也能运行，并规避本机环境差异。
- **源码仓库**：完整源码、SPEC 与产品事实随仓库提供。

## 容器构建与运行（2026-11-17 实测）

构建与启动已验证通过（本机 Docker 29.9.2 / Desktop）：

```bash
# 默认源（海外网络）
docker build -t mapsmith:v0.1 .

# 国内网络：Docker Hub 与 pypi.org 直连常超时，改用镜像源
docker build \
  --build-arg PYTHON_IMAGE=docker.m.daocloud.io/library/python:3.12-slim \
  --build-arg PIP_INDEX_URL=https://repo.huaweicloud.com/repository/pypi/simple \
  -t mapsmith:v0.1 .

docker run --rm -p 8501:8501 mapsmith:v0.1
```

实测结果：镜像约 1.11 GB；容器启动后 `/api/health` 返回 `{"status":"ok"}`；
经 API 渲染徐州 PM2.5 点图成功（3000×2400 PNG）。**中文字体随包分发**
（`src/mapsmith/render/fonts/NotoSansSC.ttf`），容器内 `load_chinese_font()` 解析到
`Noto Sans SC`，不依赖系统字体，slim 基础镜像也能正常出中文。

构建参数说明：`PYTHON_IMAGE` 与 `PIP_INDEX_URL` 默认值仍是官方源，行为与旧版一致；
仅在网络受限时通过 `--build-arg` 覆盖。

## 运行时产物与会话持久化（2026-11-18）

`out/` 是唯一的产物目录，容器里挂载它就能把「图」和「会话历史」一起持久化：

| 子目录 | 内容 |
| --- | --- |
| `out/web/<request_id>/` | 每次出图的 PNG / PDF |
| `out/uploads/` | 用户上传的原始文件 |
| `out/sessions/<session_id>.json` | **历史会话**（v0.2 新增，一个会话一个 JSON） |

会话写入走「临时文件 + `os.replace`」，进程中断不会留下半个 JSON；单个会话最多
200 条消息、2 MB。会话只存展示字段（角色、文本、错误、渲染结果），附件与过程态不落盘。
接口不可用时对话照常可用，只是不保存历史（降级而非报错）。

## 已知限制（容器形态）

1. **容器内不自带 LLM**。`/api/health` 的 `llm_configured` 只表示「base_url / api_key /
   model 三项参数齐备」，默认值指向 `127.0.0.1:11434`（Ollama）且 `api_key` 有占位值
   `ollama`，因此在**任何**环境——包括没有 LLM 的容器里——都会报 `true`。它不等于
   「可连通」。容器内的对话入口需要额外提供 LLM（挂载 `.env` 或设
   `MAPSMITH_LLM_BASE_URL/API_KEY/MODEL`）；纯表单出图不依赖 LLM。
2. 容器只读交付源码与前端产物，`/app/out` 为挂载卷；产物持久化需自行挂载。
3. 镜像不含 Node，`web/dist/` 是入库的构建产物，改前端需在宿主重建后再构建镜像。

## 明确不做

- 不生成二维码。
- 公网部署不作为验收前提；仅在具备可用的公网主机与授权时，作为可选加分项执行。
