## 复核对返工条目的追加发现（2026-11-11，第二人复核）

第 7 条标为「通过」不成立。复核人实际打开 `out/t24_rework.png` 后看到：标题为
`<区域><指标><时间>图`，即模板占位符被直接印在图上；图上指北针同时压在气泡上。

根因定位在审图员规则库，不在 `loop.py`，也不在 `apply_spec_patch`：

| 环节 | 结论 |
| --- | --- |
| `kb/reviewer_rules.json` | R01 的 `fix_spec_patch` 为 `{"title": "<区域><指标><时间>图"}`，R05、R10 同样含 `<...>` 占位符 |
| `loop.run` | 取 `_first_patch(verdict)` 交给 `apply_spec_patch`，逻辑正确 |
| `apply_spec_patch` | 忠实写入补丁内容，去掉了标题的真实值后写回占位符 |
| 第 2 轮渲染 | 用占位符标题出图，随后 `allow_render` 放行，流程记为「通过」 |

即：返工流程把图改坏了，而流程本身认为成功。这比「未修复」更严重。

**护栏**：新增 `src/tests/test_reviewer_rules_guard.py`（10 个用例），锁定
「残留占位符规则必须与登记表 `KNOWN_PLACEHOLDER_RULES` 一致」。规则库修正后，
该测试会失败并要求同步移除登记，避免问题悄悄消失。

**归属**：`kb/reviewer_rules.json` 属审图员窗口（T19），本次未跨窗口修改规则内容。

**结论调整**：第 7 条当轮判定由初判「通过」修正为 **未通过（返工产物不可交付）**，列入阻塞项；上方 13 条表格已同步为「未通过（当轮）」。
