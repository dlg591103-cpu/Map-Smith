### 4.2 审图 FAIL 与返工（T24 第 7 条）

- 该场景中原始标题本身缺时间，因此第 2 轮仍不满足 R01，属输入缺陷的预期结果；T24 记录中的「占位符被印上图」已由 T25 修复。

### 4.3 超时兜底（T24 第 8 条 / SPEC V0.1 第 7 节第 8 条）

用可控时钟强制超时：

- `status=rendered`、`round_no=0`、PNG 294,240 B（有图，不空白）。
- `LoopResult.notes` 含「审查未完成（超时）」；`result.spec.notes` **不含**该文字。
- 对照实验：同一 spec 的 `notes` 追加「独立验收标记：审查未完成（超时）」后，PNG SHA 由 `b9d92205ed36035a` 变为 `99be061a7fdb37a2`，证明 **notes 会被绘制到图面**。

结论：超时状态只回到接口 notes，未写到图面，与 T24 阻塞项 1 一致，仍未满足。

## 5. 阻塞项

### 5.1 `package.py` 产物不可一键启动（新增代码，阻塞）

- 实际执行 `python package.py --out out/accept-pr27/dist/mapsmith.zip`：产出 **82 个条目**，顶层只有 `src/`、`run.ps1`、`run.sh`、`Dockerfile`、`docker-compose.yml`、`package.py`、`README.md`。
- zip 内 `web/` 条目为 **0 个**；解压后在产物根目录调用 `mapsmith.server.index()`，返回 **HTTP 503**，正文为「MapSmith 前端未构建；请先执行：cd web && npm install && npm run build」。
- 与 `package.py` docstring「zip 解压后即可用 run.ps1 / run.sh 一键启动」不符；与 [T24 记录](T24-端到端.md) 第 12 条「zip 解压一键启动」的证据不符。
- 修复方向：把 `web/dist/` 打进 zip（或明确本脚本仅供无前端场景），并在打包后校验 `web/dist/index.html` 存在。

### 5.2 超时状态未标注在图面（既有代码，T24 记录已列为阻塞）

- 见 4.3。SPEC 第 7 节第 8 条要求「超时或达上限时仍有图返回，并标注审查状态」；T24 记录明确将「标注只在 `LoopResult.notes`、PNG 无文字」列为阻塞项。
- 本 PR 未改 `loop.py`，问题原样存在。修复方向：兜底渲染前把审查状态并入 `spec.notes`，或由渲染层叠加；修复后需重跑 T24 第 8 条并更新记录。
