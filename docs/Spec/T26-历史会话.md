# T26 历史会话：落盘、侧栏「最近」列表与恢复

> 依据：`docs/facts/01-产品定义与用户.md`、`docs/工程规则.md` 第 2、7 节。
> 问题现状：前端只用 `sessionStorage` 存最后 20 条用户原话，仅用于侧栏展示；
> 刷新或关闭标签页即丢失，点不开恢复，服务重启后也无法继续追问。

## 1. 目标

- 对话按「会话」持久化到服务端磁盘；刷新页面、重启服务、换浏览器都能看到同一份历史。
- 侧栏「最近」由占位文本改为会话列表：标题 + 更新时间；点击恢复整段对话并可继续追问；支持删除。
- 会话接口不可用时对话本身照常可用（降级为不保存历史），不影响出图。

## 3. 存储格式与规则

- 目录：`<output_dir>/sessions/`，一个会话一个 `<id>.json`；容器挂载 `out/` 即可一并持久化。
- 会话 ID：`s_YYYYmmdd_HHMMSS_xxxxxx`；白名单正则 `^s_[A-Za-z0-9_]+$`。非法 ID 一律按「不存在」处理（404），不暴露目录规则。
- 字段：`id / title / created_at / updated_at / messages[]`；`messages` 每项只保留 `id / role / text / error / result`。
- 不落盘：`stage`（当次请求进度）、CRS 弹窗状态、上传 `upload_id`（服务重启即失效）。
- 标题：取首条用户原话去掉附件行后截断 24 字；首轮定下后不随后续轮次改写；空会话占位标题为「新对话」。
- 容量：保留最近 200 条消息；序列化超过 2 MB 时从最旧的消息开始丢弃，至少保留最新一轮。
- 写入：临时文件 + `os.replace` 原子替换；列表里跳过损坏文件，不影响其它会话。
- 新建会话只返回 ID 空壳，不落盘；第一条消息保存时才创建文件，避免侧栏被空条目占满。

## 4. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/sessions` | 新建空会话，返回 `{id,title,created_at,updated_at,message_count,messages:[]}` |
| GET | `/api/sessions` | `{"sessions":[...]}`，按 `updated_at` 倒序 |
| GET | `/api/sessions/{id}` | 完整会话；不存在或 ID 非法 → 404 |
| PUT | `/api/sessions/{id}` | body `{messages, title?}`，保存并返回元信息；payload 非法 → 400 |
| DELETE | `/api/sessions/{id}` | `{"ok": true}`；不存在 → 404 |

## 5. 验收条件

1. 新建对话 → 发一句 → 刷新页面：侧栏「最近」出现该会话，标题为首条原话。
2. 点击该会话：完整恢复用户与助手消息，含地图结果卡与 PNG 链接（产物仍在磁盘时可访问）。
3. 恢复后继续追问：后端收到的 `history` 包含此前用户原话；仍处追问状态时不会从头再问。
4. 重启服务后第 1–3 条仍成立。
5. 删除会话：列表移除；删除当前会话后自动新建空对话；删除不存在的会话返回 404 且前端不报错。
6. 非法会话 ID（含路径穿越）不会读写到 `sessions/` 之外。
7. 未配置模型时：只提示未配置，不影响列表与恢复。
8. `python -m pytest` 全量通过（`tests/test_server.py` 需在允许建 socket 的环境运行）。
