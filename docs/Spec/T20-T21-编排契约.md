## 2. summary 回灌契约（T20）

`inspect.profile_points()` 返回的 `DataProfile` 就是回灌给 Cartographer 与 Reviewer 的数据摘要，字段固定如下：

```json
{
  "n_valid": 5,
  "total": 10,
  "completeness": 0.5,
  "cover": 0.0195,
  "decision": "degrade",
  "reason_lines": ["站数：有效 5 个（成面阈值 ≥10）", "覆盖度：1.95%（阈值 ≥50%）", "结论：降级为点图 / 气泡图"],
  "summary": "徐州国控站点：PM2_5_24h 有效值 5 个（共 10 个站点，完整度 50%），最高 58.0、最低 45.0。降级为点图 / 气泡图。",
  "value_min": 45.0,
  "value_max": 58.0,
  "value_mean": 51.4,
  "measurement_crs": "EPSG:4548",
  "hull_area_km2": 217.3,
  "study_area_km2": 11134.5
}
```

规则：

1. Agent 只读 `summary`、`decision`、`reason_lines` 与数值字段，不读 `GeoDataFrame`、不接触原始数据。
2. `decision` 取值 `idw | degrade | reject | field_missing`，Cartographer 据此决定 `map_type` 与图种；`reject` 时不产出 spec，回到反问。
3. `reason_lines` 三行必须原样写入 `MapSpec.notes`，不得改写或省略。
4. 每个工具返回的 `summary` 是自然语言，是可交付内容的一部分（facts/05 返回契约）。

## 3. 状态机（T21）

```
request
  │
  ├─ 缺区域 / 时间 / 指标 ──→ needs_input（最多 2 问，不猜默认值）
  │
  └─ 齐 ──→ LOAD ──→ INSPECT ──→ MAP ──→ RENDER ──→ REVIEW
                     │              ▲                   │
                     │ reject       └────── REWORK ─────┤ fail 且 round < 2
                     ▼                                  ├ fail 且 round = 2 → 出图 + 附意见
                  needs_input                            └ timeout / round > 8 → 出图 + 「审查未完成（超时）」
```

状态枚举：`needs_input | loaded | mapped | rendered | reviewing | reworked | fallback | failed`。

终止条件只有三种：`rendered`、`needs_input`、`failed`。任何情况下都不返回空白图或错误页（SPEC 第 4 节第 7 条）。

## 4. 接口

```python
from dataclasses import dataclass, field
from pathlib import Path
from typing import Any, Callable, Literal, Mapping

@dataclass
class LoopResult:
    status: Literal["rendered", "needs_input", "failed"]
    round_no: int                    # 实际执行的审查轮次，0 表示未进入审查
    elapsed: float                   # 秒
    spec: dict[str, Any] | None
    png: Path | None
    review: dict[str, Any] | None
    questions: list[str] = field(default_factory=list)
    notes: list[str] = field(default_factory=list)

def run(
    request: Mapping[str, Any],
    *,
    load_fn: Callable[[Mapping[str, Any]], Any],
    map_fn: Callable[[Any], Mapping[str, Any]],
    render_fn: Callable[[Mapping[str, Any]], Path],
    review_fn: Callable[..., Mapping[str, Any]] | None = None,
    clock: Callable[[], float] = time.monotonic,
    timeout: float = 60.0,
    max_rounds: int = 8,
    deny_limit: int = 2,
) -> LoopResult: ...
```

依赖注入的理由：编排不绑定 LLM、网络或真实渲染，测试可用替身函数覆盖所有分支。

`request` 约定字段：`place`、`time`、`metric`，任一为空即进入反问分支。

## 5. 轮次与计时归属

| 项 | 归属 | 约定 |
| --- | --- | --- |
| 60 秒总超时 | `loop.run` | 从入口起算，含加载、制图、渲染、审查；不是每环节各 60 秒（facts/04） |
| 否决上限 2 轮 | `reviewer.review` 的 `round_no` | 第 2 轮 fail 仍允许出图 |
| 全局上限 8 轮 | `loop` 与 `reviewer` 双重保护 | `round_no > 8` 时 reviewer 直接放行；loop 也不再开新一轮 |
| 单轮剩余时间 | `loop` 传给 `review` 的 `timeout` | 取 `timeout - elapsed`，不足时按超时兜底 |

超时兜底顺序：若已有 `spec` 且 `png` 为空，先尝试渲染一次；渲染失败则 `status=failed` 并附原因，不伪造图片。

## 8. 错误处理

| 情况 | 处理 |
| --- | --- |
| 加载失败（文件缺失、字段缺失） | `status=failed`，`notes` 写明原因与可用字段 |
| `decision=reject` | 不产出 spec，回到 `needs_input`，问题取自 summary |
| 制图返回非法 spec | 交由 `spec.py` 校验，校验失败即 `failed`，不进入渲染 |
| 渲染抛异常 | 捕获后 `failed`，保留 spec 与异常文本，不返回空图 |
| 审查抛超时 | 按「审查未完成（超时）」兜底出图，`notes` 记录已完成的问题 |
